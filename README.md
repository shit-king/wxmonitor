# 微信会话监听器

这是一个适配 Windows 微信 4.1.x 的纯 UI Automation 会话监听器。监听逻辑参考
[`pywechat/pyweixin`](https://github.com/Hello-Mr-Crab/pywechat) 的
`Monitor.listen_on_chat`：

- 为每个已打开的聊天窗口维护已经浏览过的历史区段；
- 轮询微信公开给 Windows UI Automation 的消息控件；
- 使用 RuntimeId 判断哪些消息已经记录；
- 向上滚动时，保存第一次进入可见区域的历史文字；
- 微信重建控件、RuntimeId 全部变化时，通过内容序列对齐恢复；
- 分别保存每个会话、每个独立聊天窗口的监听状态。

本项目是独立实现，不需要安装或导入 `pywechat`。

## 隐私边界

监听器不会：

- 截图或使用 OCR；
- 读取、复制或解密微信聊天数据库；
- 扫描微信进程内存；
- 注入 DLL 或 Hook 微信；
- 监听全局键盘；
- 自动点击、滚动或切换会话；
- 自动发送消息；
- 下载或读取文件内容；
- 保存图片、视频、语音、位置或小程序内容。

它只读取微信已经公开给 UI Automation 的：

- 当前聊天标题；
- `chat_message_list` 中当前可见的双方普通文字和文字引用回复；
- 文件卡片公开显示的文件名或描述；
- 链接卡片公开显示的标题、摘要或地址。

## 启动

双击项目根目录的：

```text
run_wechat_monitor.bat
```

或者在项目根目录运行：

```powershell
..\.venv\Scripts\python.exe -m wechat_monitor.app
```

## 使用方法

界面提供两种模式：

### 普通模式

1. 打开微信主窗口并进入一个聊天会话。
2. 如果需要同时监听多个固定会话，可在微信中把这些会话打开为独立聊天窗口。
3. 微信窗口可以在后台、被其他窗口遮挡或最小化到任务栏。
4. 选择“普通模式”，点击“开始监听”。
5. 启动时聊天窗口中已经显示的双方文字、文件名和链接会立即保存。
6. 在微信聊天窗口中向上滚动；每次新进入可见区域的历史内容都会保存。
7. 滚回本次监听期间已经浏览过的区域时，监听器会尽量避免重复记录。
8. 在监听器列表中双击一条记录可查看完整文字。

### 手动多选模式

1. 在监听器中选择“手动多选模式”；群聊建议填写“我的微信昵称”。
2. 在微信聊天窗口中右键任意消息，选择“多选”，但不需要勾选消息。
3. 点击监听器的“开始监听”。
4. 回到微信，用鼠标滚轮或滚动条手动浏览聊天记录。
5. 监听器只读取当前可见的多选消息，不会点击、勾选、滚动或退出多选。

多选消息如果自带完整日期和时间，会优先记录该精确时间；否则使用该消息之前最近的
微信时间分隔行。多选模式通常可以比普通模式更可靠地获得发送者，群聊也会尝试解析
具体成员。

“我的微信昵称”默认填写为 `JJF`。普通模式和多选模式都会从本人发送内容的开头移除
该昵称前缀；对方消息正文中正常出现的 `JJF` 不会被删除。修改昵称后会按新昵称处理。

记录保存在：

```text
%LOCALAPPDATA%\WeChatVisualMonitor\wechat_text_monitor.db
```

点击“打开数据目录”可以直接打开该位置。

### 数据库字段

`monitor_events` 表包含：

- `captured_at`：监听器实际读取到该消息的时间；
- `sent_at`：微信时间分隔行推导出的发送时间，无法推导时为空；
- `message_order`：当前可见聊天区域中从上到下的消息顺序；
- `conversation`：会话名称；
- `message_type`：`text`、`quote`、`file`、`link` 或 `card`；
- `direction`：`sent`、`received` 或 `unknown`；
- `sender`：单聊中为“我”或对方会话名称；
- `text`：消息正文、文件名或链接卡片文字；
- `source`、`fingerprint`：采集来源和去重标识。

旧版本数据库会自动新增这些列，已有记录保留；由于旧记录没有方向和发送时间来源，
迁移后它们的 `direction` 为 `unknown`，`sent_at` 和 `message_order` 为空。

微信没有通过 UIA 提供真实发送秒数，因此界面保留真实的分钟时间，并用“顺序”列
区分同一分钟内消息的先后。监听器自身的 `captured_at` 精确到毫秒，但它表示读取
时间，不冒充消息发送时间。

## 与 pyweixin 的取舍

本监听器采用 `listen_on_chat` 的 RuntimeId 增量轮询思路，但没有采用
`listen_on_newMessages` 自动遍历未读会话的方式。后者需要点击或滚动微信会话列表，
可能切换当前聊天并打断用户输入。本监听器只监听用户已经打开的主窗口会话和独立聊天
窗口，因此行为更可控，也不会改变微信界面状态。

## 当前限制

- 已在微信 4.1.12.24 验证最小化状态下仍可读取 UIA 消息控件；如果未来版本在
  最小化后折叠控件树，监听会等待窗口恢复。
- 主窗口一次只能显示一个会话；切换会话时会分别维护已浏览区段。
- 未打开的会话不会被自动点击，因此其完整消息要在打开后才能监听。
- 只能记录微信实际加载到 UIA 控件树中的文字；尚未滚动到的历史不会自动加载。
- 同一次监听期间会通过 RuntimeId 和上下文序列避免重复。微信完全退出重启后，UIA
  不提供稳定的消息唯一编号，重新浏览相同历史时可能出现重复记录。
- 大幅拖动滚动条跳到完全不连续的历史位置时，该位置当前可见的文字会作为一个新区段
  保存。
- 普通模式下，微信只在聊天流中间歇显示时间分隔行，并不总是向 UIA 暴露每条消息的
  独立精确时间。`sent_at` 因此通常是当前消息之前最近一个可见时间分隔行的时间；
  没有可见分隔行时为空。手动多选模式若公开完整时间则优先使用完整时间。
- 单聊中，带会话名称前缀的记录标为 `received`，其余记录标为 `sent`，发送者为
  “我”。普通模式下群聊没有稳定的方向和成员字段，因此标为 `unknown`；手动多选
  模式会解析多选行公开的成员名称，填写本人昵称后可判断本人和其他成员。
- 群成员昵称本身含空格时，若 UIA 把发送者和正文拼成单行文本，可能存在拆分歧义。
- 微信 4.1.12.24 的可访问名称前缀并非始终存在，所以单聊方向仍可能出现误判。
- 微信升级可能修改 AutomationId 或控件类名，需要重新适配。

## UIA 诊断

先打开微信聊天窗口，再运行：

```powershell
.\.venv\Scripts\python.exe -m wechat_monitor.diagnose
```

诊断只输出窗口数、控件数量和关键控件是否可用，不输出联系人名称或聊天正文。
